# X-Ray Mirror（复现与工程化版本）

在浏览器里用摄像头实时"透视"自己的头和手：颅骨、大脑、面部肌肉、眼球和手骨的真实 3D 模型被配准到你的脸和手上，随头部转动、张嘴和手指弯曲同步运动。

本项目把原始的单文件页面 `original/X-Ray Mirror.html` 拆分成了一个 Vite 工程。模型数据、几何解码、着色器、配准和标签算法都原样保留，没有用任何简化几何体或图片替代。

- 视频只在本机浏览器内处理，不会上传到任何服务器。
- 解剖模型是一位成年人的真实 3D 数据集，按比例贴合到你的头部，展示的是结构的典型位置，不是对你本人的扫描，也不是医疗工具。

## 快速开始

需要 Node.js 18 或更高版本。

```bash
npm install
npm run dev
```

打开 `http://localhost:5173`，点击 **Start camera** 并允许摄像头；没有摄像头时点击 **Try the demo (no camera)**，或直接打开 `http://localhost:5173/#demo`。

`npm install` 结束时会自动运行 `scripts/setup-assets.mjs`：把 MediaPipe 的 wasm 运行时复制到 `public/wasm/`，并把人脸、手部两个追踪模型（共约 11.6 MB）下载到 `public/models/`。下载失败不影响使用，页面会改为在线加载这些文件。之后可以用 `npm run setup` 重试。

## 语言与讲解

界面有中文和英文两套，默认跟随浏览器语言，快捷条最右边的按钮可以切换，也可以在网址里用 `?lang=zh` 或 `?lang=en` 指定（展台模式下可以写成 `?kiosk&lang=zh`）。

打开标签后，点一下任意标签（或它的锚点），屏幕下方会出现该结构的一句话讲解。设置里的“标签显示中英双语”可以让标签同时显示两种语言。术语和讲解文字集中在 `src/anatomy/terms.js`，界面文字在 `src/i18n.js`。

## 界面与展台模式

画面铺满整个窗口。底部快捷条可以切换图层预设、X-ray 与 Solid、标签，以及打开设置抽屉和全屏；其余设置都在抽屉里。

用于无人值守的展台时，在网址后加 `?kiosk`，例如 `https://你的网址/?kiosk`：

- 页面打开后自动启动摄像头（需要事先在浏览器里对该网址允许过摄像头），失败会每 5 秒重试。
- 画面里 2.5 秒没有人时显示"请站到镜头前"的引导提示。
- 无人 20 秒后，所有设置恢复默认，下一位观众从初始状态开始。
- 设置入口对观众隐藏；工作人员按键盘 `S` 键可以打开设置。
- 运行期间保持屏幕常亮。

## 性能

3D 图层的渲染分辨率会按实测的每帧耗时自动升降，以维持摄像头的帧率；当前分辨率和帧耗时显示在追踪数据面板的 render 一行。画面里没有手时，手部检测每 3 帧才运行一次，出现手后恢复每帧检测。

## 打包成单个 HTML 分享

```bash
npm run single
```

生成 `share/xray-mirror.html`（约 3 MB）：程序和解剖模型都在这一个文件里，可以直接发给别人，双击用 Chrome 或 Edge 打开。人脸和手部追踪的运行时与模型在点击开启摄像头时从网上加载（jsDelivr 和 Google 存储，约 20 MB），所以对方需要能访问这两个地址；演示模式不需要联网。

```bash
npm run single:offline
```

生成 `share/xray-mirror-offline.html`（约 30 MB）：追踪运行时和模型也一并内嵌，完全不需要网络。

两个文件都不带离线缓存，也不会被提交到仓库（`share/` 已在 `.gitignore` 里）。手机上直接打开本地 HTML 文件通常拿不到摄像头权限，手机使用仍需通过 HTTPS 网址。

## 测试

```bash
npm test
```

共 14 项，不需要浏览器。其中配准测试会构造一个已知脸型、已知张嘴角度的“假人”，检查拟合结果并打印重投影误差（目前约 1 像素，基于 1280×720 画面）。调整 `src/tuning.js` 或配准算法后，用它确认没有退步。`npm run bench` 则对比滤波的滞后和抖动。

## 加载与离线

首次打开时顶部有进度条。生产构建带有离线缓存（`public/sw.js`）：第一次访问后，页面、模型和运行时都存在本机，之后打开不再下载，断网也能运行；每次重新构建部署会自动换用新缓存。开发模式（`npm run dev`）不启用离线缓存。

## 在手机上测试

手机浏览器只在 HTTPS 页面上开放摄像头，所以要用带自签名证书的模式：

```bash
npm run dev:phone
```

1. 手机和电脑连同一个 Wi‑Fi。
2. 终端会显示一个 `Network: https://192.168.x.x:5174/` 地址，在手机浏览器里打开它（注意是 `https`）。
3. 浏览器会提示证书不受信任，因为证书是本机临时生成的。iPhone 的 Safari 点"显示详细信息"→"访问此网站"，安卓的 Chrome 点"高级"→"继续前往"。
4. 点 **Start camera** 并允许摄像头。

首次加载要下载约 20 MB。如果手机打不开这个地址，检查电脑防火墙是否放行了 5174 端口，以及路由器是否开启了"AP 隔离"。

## 功能

- 摄像头实时画面，镜像显示
- 人脸关键点检测，头部位置和旋转跟踪，下颌开合
- 颅骨、大脑、肌肉、眼球、头部轮廓、手骨六个图层独立开关
- 3D 模型与真人面部实时配准（姿态矩阵加 13 个关键点的屏幕对齐）
- 手部 21 个关键点驱动手掌和 15 根指骨
- X-Ray 与 Solid 两种渲染效果，亮度可调
- 左右、上下剖切，以及跟随食指指尖的 X-Ray Lens
- 整体大小、宽、高、深和三个方向位置的手动校准
- 解剖标签（头部 26 个、每只手 5 个）、追踪数据面板、FPS
- 设置保存在浏览器本地（`localStorage` 的 `xr_settings`）
- 摄像头异常处理和无摄像头的 Demo 模式

## 模型数据格式

`public/anatomy/anatomy.bin`（2,032,482 字节）包含 23 个网格，共 113,248 个顶点、225,499 个三角面。`meta.json` 里每个网格有一条记录：

- `offV`、`nv`：顶点数据的字节偏移和顶点数。每个坐标是 16 位无符号整数，按 `min + q / 65535 * size` 还原成厘米。
- `offI`、`ni`：索引数据的字节偏移和索引数，16 位无符号整数。
- 法线在加载时用 `computeVertexNormals` 计算。

`meta.json` 还包含标签锚点 `labels`、下颌转轴 `jawPivot`、人脸配准点 `fit` 和 Demo 用的手部关键点 `demoHand`。

运行 `npm run extract` 可以从 `original/X-Ray Mirror.html` 重新生成这两个文件。

## 相对原版的改动

除了眼球上新增的虹膜环和瞳孔，`?still#demo` 的静态帧与原版一致。后续的改进计划见 [ROADMAP.md](ROADMAP.md)，手感相关的常数集中在 `src/tuning.js`。相对原版的改动：

| 改动 | 原因 |
|---|---|
| 新增 Demo 按钮和 "Switch to the camera" | 原版只能靠手动输入 `#demo` 进入 Demo |
| 状态栏常驻显示 FPS | 原版只在追踪数据面板里显示 |
| 标签列向内收，保证最宽的文字不出画面 | 原版手靠近画面边缘时标签被裁掉 |
| 启动失败或切换模式时释放摄像头 | 原版失败后摄像头仍然开着 |
| 摄像头中途断开时回到开始界面并提示 | 原版没有处理 |
| 区分"没有摄像头""摄像头被占用""非 HTTPS"三种错误 | 原版只区分"被拒绝"和"其他" |
| 读取本地设置时校验类型和取值 | 损坏的设置不应让页面出错 |
| Demo 的手指会缓慢弯曲 | 不用摄像头也能看到手骨跟随手指弯曲；`?still` 下保持原版姿态 |
| 追踪模型和 wasm 优先从本站加载 | 可离线部署，不依赖外部网站 |
| 显示"被检测的那一帧"而不是实时视频 | 画面与模型来自同一时刻，模型不再落后于人 |
| One Euro 自适应滤波替换固定系数插值 | 静止更稳，快速运动时滞后更小（`npm run bench` 可量化对比） |
| 自动适配头型（"Auto fit to my face"） | 按脸宽、脸长自动拉伸模型，换人自动重置，滑块只作微调 |
| 全屏展示布局、快捷条、设置抽屉、展台模式 | 面向科普展示：打开即用，无人值守 |
| 渲染分辨率自适应、手部检测按需降频 | 在手机上维持帧率 |
| 手挡在脸前时隐藏其后的头部模型 | 遮挡关系正确 |
| 手骨粗细按真实骨长计算；手掌跟随中指和无名指的指根 | 手指朝向镜头时骨头不变细；握拳时掌骨不脱节 |
| 眼球随视线转动，并加了虹膜环和瞳孔 | 数据集的眼球没有纹理，不加标记看不出转动。这是唯一一处非数据集的几何体 |
| 下颌角度由下巴关键点求解；下脸肌肉、皮肤轮廓随下颌运动 | 原版下颌开合幅度偏小，且张嘴会带动整个头模缩放 |
| 把数据集里归在颅骨网格下的下颌牙槽部分拆出来，随下颌一起运动 | 否则张嘴时下颌骨上缘和下牙留在原地 |
| 中英文界面、中文标签、点击讲解 | 面向中文观众的科普展示 |
| 加载进度条、离线缓存、自动化测试、部署配置、许可与隐私声明 | 上线所需 |

## Demo 模式的测试开关

- `#demo`：动画 Demo。
- `?still#demo`：只画一帧固定姿态，用于和原版截图对比。
- `?dump#demo`：1.5 秒后把所有图层合成一张图片盖在页面上，用于测试。
- `?handx=0.47#demo`：把 Demo 的手移到脸前，用于测试遮挡。
- `?face=1.06,0.94#demo`：假装观众的脸比模型宽 6%、短 6%，用于测试自动适配（数据面板的 head shape 乘以 screen fit 的 scale 应接近这两个数）。

## 部署

```bash
npm test
npm run build
```

产物在 `dist/`（约 33 MB），是纯静态文件，所有路径都是相对路径。

**Netlify 或 Cloudflare Pages（推荐）**：在托管平台上连接本仓库，构建命令 `npm run build`，发布目录 `dist`。仓库里已有 `netlify.toml` 和 `public/_headers`（缓存策略、只允许本页面使用摄像头等响应头），两个平台都会读取。

**其他静态服务器**：把 `dist/` 整个放上去即可。注意三点：

1. **必须用 HTTPS**（或 `localhost`），否则浏览器不允许访问摄像头。
2. `.wasm` 文件要按 `application/wasm` 类型返回。
3. `sw.js` 和 `index.html` 不要设置长期缓存，否则更新后观众看到的还是旧版本。

如果不想托管 wasm 和追踪模型，可以在构建后删掉 `dist/wasm` 和 `dist/models`，页面会改从 jsDelivr 和 Google 存储在线加载，这时观众的网络需要能访问这两个地址。

展台电脑的建议做法：用 Chrome 打开 `https://你的网址/?kiosk&lang=zh`，对该网址允许一次摄像头，然后用 Chrome 的 kiosk 启动参数全屏运行。

许可、署名、隐私和非医疗用途声明见 [NOTICE.md](NOTICE.md)。
