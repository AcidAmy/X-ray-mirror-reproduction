# X-Ray Mirror（复现与工程化版本）

在浏览器里用摄像头实时"透视"自己的头和手：颅骨、大脑、面部肌肉、眼球和手骨的真实 3D 模型被配准到你的脸和手上，随头部转动、张嘴和手指弯曲同步运动。

本项目以原始单文件页面 `original/X-Ray Mirror.html` 为基础拆分成 Vite 工程，初始版本保留原模型数据及解码、着色器、配准和标签实现，随后增加跟踪改进、双语讲解、CT/MRI 教学视图和交互。它是基于原件的衍生开发，不是全部从零原创。

**授权核查中（2026-11-16）**：已确认下载原件与仓库文件的 SHA-256 一致，但尚未确认原程序的改编和再分发许可；BodyParts3D 的数据许可不等于整个程序的许可。来源证据、联系草稿和待办见 [NOTICE.md](NOTICE.md)。

- 视频只在本机浏览器内处理，不会上传到任何服务器。
- 解剖模型是一位成年人的真实 3D 数据集，按比例贴合到你的头部，展示的是结构的典型位置，不是对你本人的扫描，也不是医疗工具。

## 快速开始

需要 Node.js 18 或更高版本。

```bash
npm install
npm run dev
```

打开 `http://localhost:5173`，点击 **Start camera** 并允许摄像头；没有摄像头时点击 **Try the demo (no camera)**，或直接打开 `http://localhost:5173/#demo`。

`npm install` 结束时会自动运行 `scripts/setup-assets.mjs`：把 MediaPipe 的 wasm 运行时复制到 `public/wasm/`，并把人脸、手部两个追踪模型（共约 11.6 MB）下载到 `public/models/`。下载失败不影响使用，页面会改为在线加载这些文件。之后可以用 `npm run setup` 重试。

## 语言与讲解

界面有中文和英文两套，默认跟随浏览器语言，快捷条最右边的按钮可以切换，也可以在网址里用 `?lang=zh` 或 `?lang=en` 指定（展台模式下可以写成 `?kiosk&lang=zh`）。

打开标签后，点一下任意标签（或它的锚点），屏幕下方会出现该结构的一句话讲解。设置里的“标签显示中英双语”可以让标签同时显示两种语言。术语和讲解文字集中在 `src/anatomy/terms.js`，界面文字在 `src/i18n.js`。

## 断层三视图

快捷条上的“断层”打开三视图面板：轴位、冠状位、矢状位三张剖面，都经过同一个点（十字准星）。

窄屏（不超过 700px）采用上下分区：人体画面在上、切片面板在下，画面保持相机比例，不被面板遮挡。默认显示轴位，顶部可切换方向或选择“三视图”并排对照；“收起 / 展开”让出更多画面空间。“设置 / 读数”打开可滚动的完整控件，包括 MRI 底图、展台交互和结构跳转。再次点击方向按钮可返回切片。快捷条的“断层”可关闭整个面板。小尺寸手机的顶部状态栏和快捷条也会压缩排列。

- 默认“模型剖面”是用平面直接切三维模型得到的，所以与镜像里的模型完全对齐。它是图谱式的示意剖面，不是 CT 或 MRI 图像。
- 在任意一张图上拖动可以移动准星，滚轮或图下方的滑块可以换层面；另外两张图和镜像里的三个彩色平面同步移动。
- 面板显示准星的坐标（厘米，相对模型原点）、所在组织和最近的标注。点“最近标注”或从“跳到结构”里选一项，会跳到该结构并显示讲解。
- 打开标签后，点镜像里的标签，三视图也会跳到该结构。
- 左右方向按 CT、MRI 的看片习惯：图像左侧是人的右侧；矢状位面部朝左。
- 剖面里下颌是闭口姿态，不随张嘴变化。

两点限制：大脑网格只有灰质表面，白质和脑室没有单独建模，准星在脑内深处时统一报告为“大脑”；“最近标注”按到标注锚点的距离判断，锚点在结构表面，所以它是就近提示，不是精确的分区边界。

剖面计算在 `src/anatomy/section.js`，面板和联动在 `src/hud/triview.js`。

## MRI 底图（阶段 6b）

打开“断层”，在“底图”选择 **MRI 影像** 或 **MRI + 模型轮廓**；勾选“三维切面显示 MRI”可将同一影像贴到头部的三个切面上。拖动、换层和跳到结构继续共用同一个模型坐标。对比度滑块调节灰度显示。

数据为 McGill **ICBM152 2009c symmetric T1**：由真实 MRI 生成的群体平均图谱，不是单个患者影像，也不是对观众的扫描。附带的 CSF、GM、WM 概率图转换为组织标签，供后续 6c 使用；当前界面的“所在组织”和“最近标注”仍根据原来的三维模型判断。

**配准限制**：离线按脑掩膜与模型大脑／小脑脑干联合包围盒做轴向仿射对齐。它用于教学中的大致位置对应，未做局部形变配准或临床精度验证，MRI 和模型轮廓会有差异，面部和颈部尤其如此。无源数据覆盖的区域显示黑色。可切回“模型剖面”查看原来的精确模型剖切。

体数据按模型坐标重采样至 0.2 cm 间距，T1 为 8 位灰度（线性插值），组织标签为 8 位离散值（浏览器最近邻采样）。选择 MRI 时才加载；失败会保留模型剖面并提供重试。网站版首次成功加载后由现有 service worker 缓存；两种单 HTML 包均内嵌 MRI，演示无需网络。

重新生成（仅维护者需要 Python + NumPy + SciPy，普通运行不需要）：

```bash
# 从下方官方来源下载 mni_icbm152_nlin_sym_09c_nifti.zip
python3 scripts/prepare-volume.py /path/to/mni_icbm152_nlin_sym_09c_nifti.zip
npm test
npm run build
```

输出 `public/volume/` 包含体数据、源文件 SHA-256、源 NIfTI 到模型坐标的变换及逆矩阵、标签定义和原始许可。数据随项目发布，不在安装阶段重新下载。

来源与许可：[McGill 官方图谱页面](https://nist.mni.mcgill.ca/icbm-152-nonlinear-atlases-2009/)，具体署名见 `NOTICE.md` 和 `public/volume/`。

## 界面与展台模式

画面铺满整个窗口。底部快捷条可以切换图层预设、X-ray 与 Solid、标签，以及打开设置抽屉和全屏；其余设置都在抽屉里。

用于无人值守的展台时，在网址后加 `?kiosk`，例如 `https://你的网址/?kiosk`：

- 页面打开后自动启动摄像头（需要事先在浏览器里对该网址允许过摄像头），失败会每 5 秒重试。
- 画面里 2.5 秒没有人时显示"请站到镜头前"的引导提示。
- 无人 20 秒后，所有设置恢复默认，下一位观众从初始状态开始。
- 设置入口对观众隐藏；工作人员按键盘 `S` 键可以打开设置。
- 运行期间保持屏幕常亮。

## 性能

3D 图层的渲染分辨率会按实测的每帧耗时自动升降，以维持摄像头的帧率；当前分辨率和帧耗时显示在追踪数据面板的 render 一行。画面里没有手时，手部检测每 3 帧才运行一次，出现手后恢复每帧检测。

## 打包成单个 HTML 分享

```bash
npm run single
```

生成 `share/xray-mirror.html`（约 7.8 MB）：程序和解剖模型都在这一个文件里，可以直接发给别人，双击用 Chrome 或 Edge 打开。人脸和手部追踪的运行时与模型在点击开启摄像头时从网上加载（jsDelivr 和 Google 存储，约 20 MB），所以对方需要能访问这两个地址；演示模式不需要联网。

```bash
npm run single:offline
```

生成 `share/xray-mirror-offline.html`（约 34.8 MB）：追踪运行时和模型也一并内嵌，完全不需要网络。

两个文件都不带离线缓存，也不会被提交到仓库（`share/` 已在 `.gitignore` 里）。手机上直接打开本地 HTML 文件通常拿不到摄像头权限，手机使用仍需通过 HTTPS 网址。

## 安装到手机主屏幕

## 加载与离线

首次打开时顶部有进度条。生产构建带有离线缓存（`public/sw.js`）：第一次访问后，页面、模型和运行时都存在本机，之后打开不再下载，断网也能运行；每次重新构建部署会自动换用新缓存。开发模式（`npm run dev`）不启用离线缓存。

## 在手机上测试

手机浏览器只在 HTTPS 页面上开放摄像头，所以要用带自签名证书的模式：

```bash
npm run dev:phone
```

1. 手机和电脑连同一个 Wi‑Fi。
2. 终端会显示一个 `Network: https://192.168.x.x:5174/` 地址，在手机浏览器里打开它（注意是 `https`）。
3. 浏览器会提示证书不受信任，因为证书是本机临时生成的。iPhone 的 Safari 点"显示详细信息"→"访问此网站"，安卓的 Chrome 点"高级"→"继续前往"。
4. 点 **Start camera** 并允许摄像头。

首次加载要下载约 20 MB。如果手机打不开这个地址，检查电脑防火墙是否放行了 5174 端口，以及路由器是否开启了"AP 隔离"。

## 模型数据格式

`public/anatomy/anatomy.bin`（2,032,482 字节）包含 23 个网格，共 113,248 个顶点、225,499 个三角面。`meta.json` 里每个网格有一条记录：

- `offV`、`nv`：顶点数据的字节偏移和顶点数。每个坐标是 16 位无符号整数，按 `min + q / 65535 * size` 还原成厘米。
- `offI`、`ni`：索引数据的字节偏移和索引数，16 位无符号整数。
- 法线在加载时用 `computeVertexNormals` 计算。

`meta.json` 还包含标签锚点 `labels`、下颌转轴 `jawPivot`、人脸配准点 `fit` 和 Demo 用的手部关键点 `demoHand`。

运行 `npm run extract` 可以从 `original/X-Ray Mirror.html` 重新生成这两个文件。

## 相对原版的改动

除了眼球上新增的虹膜环和瞳孔，`?still#demo` 的静态帧与原版一致。后续的改进计划见 [ROADMAP.md](ROADMAP.md)，手感相关的常数集中在 `src/tuning.js`。相对原版的改动：

| 改动 | 原因 |
|---|---|
| 新增 Demo 按钮和 "Switch to the camera" | 原版只能靠手动输入 `#demo` 进入 Demo |
| 状态栏常驻显示 FPS | 原版只在追踪数据面板里显示 |
| 标签列向内收，保证最宽的文字不出画面 | 原版手靠近画面边缘时标签被裁掉 |
| 启动失败或切换模式时释放摄像头 | 原版失败后摄像头仍然开着 |
| 摄像头中途断开时回到开始界面并提示 | 原版没有处理 |
| 区分"没有摄像头""摄像头被占用""非 HTTPS"三种错误 | 原版只区分"被拒绝"和"其他" |
| 读取本地设置时校验类型和取值 | 损坏的设置不应让页面出错 |
| Demo 的手指会缓慢弯曲 | 不用摄像头也能看到手骨跟随手指弯曲；`?still` 下保持原版姿态 |
| 追踪模型和 wasm 优先从本站加载 | 可离线部署，不依赖外部网站 |
| 显示"被检测的那一帧"而不是实时视频 | 画面与模型来自同一时刻，模型不再落后于人 |
| One Euro 自适应滤波替换固定系数插值 | 静止更稳，快速运动时滞后更小（`npm run bench` 可量化对比） |
| 自动适配头型（"Auto fit to my face"） | 按脸宽、脸长自动拉伸模型，换人自动重置，滑块只作微调 |
| 全屏展示布局、快捷条、设置抽屉、展台模式 | 面向科普展示：打开即用，无人值守 |
| 渲染分辨率自适应、手部检测按需降频 | 在手机上维持帧率 |
| 手挡在脸前时隐藏其后的头部模型 | 遮挡关系正确 |
| 手骨粗细按真实骨长计算；手掌跟随中指和无名指的指根 | 手指朝向镜头时骨头不变细；握拳时掌骨不脱节 |
| 眼球随视线转动，并加了虹膜环和瞳孔 | 数据集的眼球没有纹理，不加标记看不出转动。这是唯一一处非数据集的几何体 |
| 下颌角度由下巴关键点求解；下脸肌肉、皮肤轮廓随下颌运动 | 原版下颌开合幅度偏小，且张嘴会带动整个头模缩放 |
| 把数据集里归在颅骨网格下的下颌牙槽部分拆出来，随下颌一起运动 | 否则张嘴时下颌骨上缘和下牙留在原地 |
| 中英文界面、中文标签、点击讲解 | 面向中文观众的科普展示 |
| 窄屏下快捷条换成两行；打开标签时提示“点一下标签可以看讲解” | 第一次使用的人不容易发现要横向滑动，也不知道标签可以点 |
| 应用清单和图标 | 可以添加到手机主屏幕 |
| 加载进度条、离线缓存、自动化测试、部署配置、许可与隐私声明 | 上线所需 |

## 部署

```bash
npm test
npm run build
```

产物在 `dist/`（约 36 MB），是纯静态文件，所有路径都是相对路径。

**Netlify 或 Cloudflare Pages（推荐）**：在托管平台上连接本仓库，构建命令 `npm run build`，发布目录 `dist`。仓库里已有 `netlify.toml` 和 `public/_headers`（缓存策略、只允许本页面使用摄像头等响应头），两个平台都会读取。

部署记录（2026-11-16）：用户确认已托管到 Netlify；本次未获得生产网址，未独立验证线上访问、摄像头和离线缓存。部署完成不代表授权核查完成。

**其他静态服务器**：把 `dist/` 整个放上去即可。注意三点：

1. **必须用 HTTPS**（或 `localhost`），否则浏览器不允许访问摄像头。
2. `.wasm` 文件要按 `application/wasm` 类型返回。
3. `sw.js` 和 `index.html` 不要设置长期缓存，否则更新后观众看到的还是旧版本。

如果不想托管 wasm 和追踪模型，可以在构建后删掉 `dist/wasm` 和 `dist/models`，页面会改从 jsDelivr 和 Google 存储在线加载，这时观众的网络需要能访问这两个地址。

展台电脑的建议做法：用 Chrome 打开 `https://你的网址/?kiosk&lang=zh`，对该网址允许一次摄像头，然后用 Chrome 的 kiosk 启动参数全屏运行。

许可、署名、隐私和非医疗用途声明见 [NOTICE.md](NOTICE.md)。

## 展台交互（阶段 6c）

- 加载 MRI 后，准星的 **MRI 体素** 单独显示灰质、白质、脑脊液，或未标注／覆盖范围外。它来自图谱概率图的最大概率类别，不能识别具体脑区、疾病或观众自身组织。“所在组织”和“最近标注”仍根据模型判断。
- 展开“展台交互”，开启“捏合手指换层”，选轴位、冠状位或矢状位。单手拇指与食指捏合后上下移动换层；松开、手丢失或出现两只手即停止。手骨隐藏时仍可检测手势。换层最多每秒十次，避免反复重算切片；需要真人确认检测阈值和手机手感。
- 开启“固定屏幕切面”会加载 MRI，在当前头部附近建立一个面向摄像头的固定平面；头部运动时，按逆姿态重新采样相交的 MRI。每秒最多约八次更新，属于教学交互。平面不随头部移动，原来的三视图仍显示解剖轴向切片；两者不是同一组层面。
- 固定模式暂停手势换层。“重新定位”把平面移到当前头部；追踪丢失后重获目标也会重新定位。模式切换和展台无人重置会关闭这两个交互开关。
- 6b 的近似配准限制继续适用。固定切面和手势需要在真实摄像头与目标手机上验收，Demo 不能替代真人测试。


## CT 教学显示（阶段 6d）

打开“断层”，将“底图”切换到“CT 影像”或“CT + 模型轮廓”。手机上先点“设置 / 读数”，选好后点击轴位、冠状位或矢状位回到切片。

- 骨窗（窗宽 2000 / 窗位 500）、脑窗（80 / 40）、软组织窗（400 / 40）是可调整的教学预设，不是诊断协议。也可拖动窗宽、窗位设置自定义范围；调窗不改变 HU 读数。
- 准星显示当前位置的近似 HU 值，源数据先重采样到模型空间，读数再三线性插值。超出数据覆盖范围时显示“超出扫描覆盖范围”，不冒充空气或水。
- 三张切片、三维贴图、固定屏幕切面、手势换层复用已有联动。切换 CT/MRI 时保留准星，分别使用自己的图像与显示设置；固定平面重新定位。
- “CT 影像”不显示模型标注点、不吸附到模型标签；“CT + 模型轮廓”才显示叠加参考。“模型组织”和“最近标注”始终来自模型，不是 CT 分割识别。
- 数据是 Google DeepMind 官方 CC BY 4.0 发布的 TCIA 头颈放疗样本 `0522c0017`，并非健康图谱，与当前 MRI 不配对。这里只做脑分割包围盒近似对齐，不表示局部结构精确重合。来源、许可和处理方法见 `NOTICE.md`、`public/ct/meta.json`。

CT 按需加载，体数据约 5.2 MiB；与 MRI 一样可缓存，首次使用 CT 后才能离线命中缓存。两个单文件版本都内嵌 CT，不依赖额外数据请求。模块在 `src/hud/volume-source.js`，调窗/采样在 `src/anatomy/volume.js`；预处理在 `scripts/prepare-ct.py`。原始 NRRD 不随项目重复分发，元数据保留下载地址与校验值。
